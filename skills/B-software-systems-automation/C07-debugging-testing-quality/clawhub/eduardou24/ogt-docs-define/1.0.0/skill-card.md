## Description: <br>
General guide for creating definition documents. Use when you need to define WHAT something IS - concepts, entities, systems, or domains. Routes to specialized sub-skills for specific definition types (business, features, code, marketing, branding, tools). <br>

This skill is ready for commercial/non-commercial use. <br>

## Use Case: <br>
Developers, documentation authors, and product teams use this skill to create definition documents that clarify what a concept, entity, system, or domain is before implementation or communication work proceeds. <br>

### Deployment Geography for Use: <br>
Global <br>

## Known Risks and Mitigations: <br>
Risk: Running the example shell commands in the wrong directory can create or remove local definition status marker files. <br>
Mitigation: Confirm the intended definition directory before executing commands such as touch, echo redirection, or rm. <br>
Risk: Generated definitions can mislead teams if they skip review or leave boundaries unclear. <br>
Mitigation: Use the documented review lifecycle and quality checklist before treating a definition as approved. <br>
